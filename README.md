# 暗区求生 / DARK ZONE SURVIVAL

[![CI](https://github.com/ShaneLxy/DarkZone/actions/workflows/ci.yml/badge.svg)](https://github.com/ShaneLxy/DarkZone/actions/workflows/ci.yml)

Cocos Creator 3.8.8 + TypeScript 的俯视角动作射击样品。以手动移动、瞄准、枪械射击和视线遮挡为核心，附带抽卡、商店、装备改装、开箱、签到、每日任务、成就与局外养成。

当前版本 **0.17.1**（与 `package.json` 一致）。探索模式包含四章：第一章“静默宿舍”、第二章“归途”、第三章“归巢”、第四章“断翼行动”（前传，含城市／营地／防守三阶段行动）。全部进度保存在本机，无账号、付费与联网功能。

第一章“静默宿舍”包含二楼寝室长廊与一楼门厅。每次行动会抽取钥匙、部分家具、丧尸点位及地面装饰。二楼两封信与一楼宿管终端可在玩家视野内调查，首次调查写入首页“剧情档案”，重复阅读不会重复计数。阅读期间暂停当前战斗，可翻阅电脑记录。老鼠和小虫偶尔从墙边掠过，每局有一至两处门灯会短暂闪烁。玩家倒地后播放三帧动作，再渐变灰屏并弹出提示。每局配一支强心剂，可原地复活并恢复 30% 最大生命。首页每日任务按设备本地时间每日 05:00 重置。

第一章撤离后解锁第二章“归途”。凛经过公交站，在第一个路口触发车辆警报，沿北向长街突围，最后与三名幽灵突击手会合。凛与存活队友共享战斗视野，小地图随视野逐步揭开。战斗弹药有限，可搜索弹药、绷带、医疗包、能量饮料和金币。翻滚可穿过丧尸和队友，墙壁、门和家具会挡住翻滚。[关卡说明与街景素材](docs/street-chapter.md)

章节与系统结构见 [架构与模块索引](docs/ARCHITECTURE.md)，版本变更见 [CHANGELOG](CHANGELOG.md)。

## 开始试玩

构建产物位于 `build/web-mobile/`，**不纳入版本管理**：从 GitHub 克隆后需先执行 `npm run build`（要求本机安装 Cocos Creator 3.8.8），再用 HTTP 服务访问，不能直接双击 `index.html` 运行。

```powershell
npm run build
npm run preview
```

电脑打开 <http://127.0.0.1:8088/>。手机连接同一局域网后，可以运行 `npm run preview -- --lan`，在手机中打开电脑的局域网地址加端口 `8088`；系统防火墙是否允许访问需要按实际环境处理。默认命令仅监听本机。

也可以通过 Cocos Dashboard 导入当前目录，使用 **3.8.8** 打开，打开 `assets/scenes/Facility.scene` 后预览。启动脚本 `Blackout` 挂载于场景内的普通子节点 **Game Bootstrap**，在运行时创建画面与 UI；Scene 根对象不挂载业务组件。

正常启动会先出现“暗区求生”首页。点击右侧“探索模式”或按 Enter 打开探索地图，点选关卡坐标查看介绍，再确认进入。进入第一章时可选择教学或直接探索。角色、宿舍素材和视野材质加载完成后才能开始。如果还开着旧预览，请停止后重新预览，或刷新浏览器。

## 教程操作示意

四步教学使用一个黑色半透明灰边气泡，尾巴指向当前真实控件。白色箭头与示意摇杆帽同步拖动：移动朝金色地面圆圈，内圈转向和外圈手动开火朝红色训练靶；AUTO开启/关闭先展示开关点击，亲手开启后展示对准才自动射击。示意图完全由Graphics绘制，没有按钮、触摸监听或输入热区。

每步循环三次后保留推出姿态；暂停、欢迎框及跳过确认冻结动画。有效拖动时淡出，停止约半秒后恢复，循环不会重启。完成、跳过及离开战斗清理图形和文字；存档继续保留原教程步骤与首次询问规则。纯动画逻辑位于 `assets/scripts/TutorialGuide.ts`，绘制位于 `TutorialGuideArt.ts`，回归入口 `tools/test-tutorial-guide.mjs`。

## 剧情线索与成就

第一版剧情档案包含三条固定线索：二楼凛寝室的 `letter_alarm`、202 寝室的 `letter_wall`，以及一楼宿管室桌面的 `warden_log`。线索只在对应楼层的固定桌边出现，必须处于玩家严格视野、视距和遮挡判定内才显示金色描边；靠近后使用“调查”按钮，桌面端也可按 E。首次调查写入本机存档（内部版本 v5）的 `clues` 与 `achievements`，重复阅读不会重复计数，不影响击杀、清场、奖励或教程。

## 双拇指辅助与自动开火

- **轻辅助瞄准默认 ON，自动开火首次 OFF**，两项独立保存在本机 profile（内部版本 v5）；v1–v5 缺字段和非布尔脏值回退默认，不改变存档兼容性。设置与战斗 AUTO 按钮同步。
- 手机主动推右杆才辅助；桌面鼠标不磁吸。只选当前严格可见、中心连线无遮挡且靠近原始输入方向的活敌人；不改视野、不显示目标标记。优先保留当前目标以防抖动。推到底仍有辅助，不以推杆强度判定脱离。
- 原始方向捕获角 0.20 rad、保留角 0.25 rad，最大修正 0.16 rad、修正角速度 1.8 rad/s。单帧转向超过 0.48 rad、输入角速度超过 3.8 rad/s，或与目标方向相反的单帧操作超过 0.045 rad，立即释放并抑制再吸附 0.22 秒。快速扫动也抑制自动开火。松手保持最后真实朝向，不追目标。
- AUTO ON 时仅实际朝向的射线第一命中是当前可见活敌人才开火；使用与子弹一致的普通 18／首领 29 半径、700 最大射程，墙、家具、旋转门扇优先阻挡。无目标是“待命”，不向整个视野乱射。松手后当前方向仍命中时可以射击；武器散布保留，自动不保证每颗弹丸命中。
- 换弹、翻滚、硬直、真实击退、倒地与换层禁止所有射击入口；自动开关仍保留 ON 并显示短原因。最后一发仍立即自动换弹。当前钥匙与开锁为即时操作；未来持续解锁／部署用 Core `shootingBlockedReason` 设置期间的禁火原因，结束清空，不额外引入状态机。控制器暂停／设置期间不推进战斗。
- 为给 AUTO 留出独立热区，右射击杆向下移动 35 个参考像素；弹药面板和其他按钮不变。按钮命中区为约 141×54 设计像素，支持另一手指移动时点击。暂停、新局、换层和复活清理辅助历史，保存的模式不丢失。

## 战斗反馈

- 开火触发沿枪械后坐方向的短促镜头冲击，强度按当前角色配置区分（凛最轻、幽灵居中、维川最强）；HUD 不随镜头移动。USP 使用独立的轻量消音音效。
- 上身模型开火时后退约 1～2.3 个逻辑像素，角度摆动约 0.8～1.8 度，在 0.085～0.13 秒内回正；火光、烟雾和抛壳挂点与模型共用变换。脚保持地面位置，碰撞与瞄准不受表现偏移影响。
- USP 枪口产生约 90 像素的小范围弱光，其他枪械约 140～160 像素，约 65 毫秒内衰减；墙体和关门后的严格暗区不会被闪光照穿。
- 实际扣血时触发屏幕边缘闪红和轻微中心染红。生命越低，单次受击闪红越久。无敌期接触不会重复触发。
- 生命比例降至 25% 或以下时，屏幕边缘按约 1.5 秒的周期闪红。血量越低，红色越深、每次持续越久。恢复到 30% 或以上时停止。
- 暂停、结算和整备时清除瞬时视觉效果，重新开始行动不沿用上次的受击或低血量状态。
- 命中敌人有短促光斑和独立轻量音效，同一时间段限频，霰弹枪多弹丸不会叠成过响的提示。
- 女主走路保留实际位移驱动的轻微缩放，不额外显示脚。军人与敌人保留左右脚交替，只有迈出的脚从身体前缘出现；待机、攻击停步、顶墙与死亡时收脚。前方按角色／枪口朝向定义，支持横移和倒退。
- 翻滚为收身、翻转、落地起身三帧，女主与军人各自使用无武器图集；全段隐藏站立持枪模型，落地后恢复。持续 0.30 秒、约移动 132 像素、冷却 2.4 秒，仍受碰撞约束。
- 火光采用暖色外焰、浅色火舌与白色内核，约 45 毫秒；贴图角色与代码角色各有实测枪口挂点，随旋转和步态缩放同步。烟雾短暂扩散消退，弹壳侧向抛出、落地反弹并淡出，受掩体和严格视野裁剪。
- 玩家和敌人实际受伤时，少量血滴从角色身后呈扇形飞出。血滴带短尾迹，约半秒内淡出。击退遇到墙、门或家具会停止，散弹枪同一发弹丸对同一敌人只触发一次击退。
- 敌人阵亡后保留原有倒地碎片与血迹。玩家致命伤后停止战斗计时，约 0.54 秒播放倒地三帧，再用约 0.28 秒转为灰屏，然后打开复活或结算对话框。使用强心剂原地恢复 30% 最大生命并获得 1.5 秒保护。

## 首次二楼宿舍教学

- 新账号首次探索先进入 `createDormRun` 的真实二楼寝室，再居中显示黑色半透明灰边框“是否进入新手教程？”（开始／跳过，首次没有不再显示）。尚未选择不记为已看过，刷新仍询问；弹窗期间冻结战斗更新及键鼠／多指触控输入，背景全屏拦截不穿透，Enter 不隐式接受。四步提示统一使用手机操作：拖动左侧摇杆移动进地面金圈 → 轻推右侧摇杆内圈瞄准红色闪烁靶而不开火 → 推动右侧摇杆外圈手动命中 → 点击 AUTO ON 并瞄准直至自动命中。只瞄准、空枪或打偏不算命中；桌面按键仍可操作。
- 战斗底部不再显示整条操作说明。训练靶位于 (470,370)，距出生点 (306,240) 约209，移动金圈保持 (306,300)。红靶以0.75秒周期脉冲，按25Hz表现时间采样，仅教学期间且满足实际视距与遮挡时绘制，不影响碰撞或命中点。
- 教学固定 seed，出生寝室内限制安全活动范围；正式敌人仍保留在同一个 Battle 中休眠，行动时间、钥匙、门、房间清场与伤害不推进。圆靶是独立逻辑对象，不是敌人，不计击败、清场、回血、任务或奖励。训练子弹不伤门、不惊动敌人；结束清空训练弹丸并恢复训练消耗的弹匣，原地解除隔离继续正常两层探索，不重生成地图或敌人。
- 每步即时保存在本机 profile 的 `tutorial` 字段；新档从 `move` 开始，旧档缺字段默认 `done`。退出、刷新后重开按保存步骤重建训练（不保存整场）；暂停／系统 hide 清理按住输入但保留训练状态。AUTO 选择始终保存，不强制改开关；若恢复时已经 ON，按提示先 OFF 再亲手 ON。
- 教学中左侧持续显示“跳过教程”，暂停页跳过复用同一二次确认（继续教学／跳过）；继续教学或 Esc 恢复原教学／暂停状态，Enter 不确认。确定后在同一 Battle、同布局原地解除训练隔离、不结算奖励，保留 AUTO 偏好。也可保存步骤返回首页；刷新后恢复未完成步骤。
- 每次进入第一章时可选择直接探索，或根据存档开始、继续、重播教学。重播从第一步开始，保留教程历史及 AUTO 偏好。第二章进入后直接探索。
- 存档内部版本为 v5（`readProfile` 兼容 v1–v5）。完成或跳过记录可以同时保留，`tutorial` 为 done 时按重播处理。旧档缺少教学进度时使用 done，已有未完成步骤可继续。

## 战术道具与声音

- **新账号没有已解锁战术道具**，首页无切换、战斗无投掷按钮，G 不消耗任何东西；当前未提供道具解锁途径。旧档缺 `tacticalUnlocked` 字段时兼容解锁手雷和震撼弹；已有字段只接受去重后的已实现类型，拒绝脏值与地雷。版本和本机存储键不变，不清档。
- 兼容旧账号：首页右上“行动道具”点击在已解锁手雷／震撼弹之间切换；单槽每局仅带一种、2次，感应地雷尚不可选。新局恢复次数、清空在途投掷和冷却。
- 沿瞄准方向投掷，墙前落点截停。手雷延迟0.32秒后爆炸，半径92、伤害48；震撼弹延迟0.26秒、半径118、普通敌人硬直0.85秒，首领缩短。两者冷却1.15秒，不隔墙影响敌人。金环／读秒显示冷却，用尽有文字反馈。
- 投掷有弧线弹体与落点圈；手雷为暖橙爆炸，震撼弹为浅蓝扩散波，无新增外部素材。暂停冻结投掷、冷却、声音和门预警。
- 枪声、开门／破门、爆炸、真实移动和翻滚产生限频声音事件，同时最多48条。门交互（成功、关闭或被挡失败）按门位置发出低强度 `door-interact`，单门0.35秒节流；实体墙封闭直线传播，木门和钢门衰减不同，仅门附近单位可听见并让位/调查，远处不会直接获得玩家坐标。
- 近处响声使单个敌人提高警觉，远处响声触发声音落点调查；调查追的是声音快照而非玩家实时位置。没看见玩家则短暂搜索后停下，即使房间原已警戒也不覆盖调查；无遮挡看见玩家才切回战斗。开门只发现相邻房间，不直接使整房警戒；已发现玩家的追击保留。

## 房门试玩重点

- 寝室、值班室、洗衣房等使用 100 耐久的可破坏木门。
- 楼梯间和宿舍楼大门使用不可破坏的铁门，分别由楼梯钥匙和大门钥匙解锁。
- 门朝远离交互者的一侧打开；转动过程持续参与遮挡，完全打开的门扇仍然是实体掩体。
- 关门遇到人会回弹，开门被挡会停住。近门敌人听到门交互或失败撞门后会短暂进入让位状态，优先沿可行方向后退/侧移，路径仍检查墙和其他门；没有安全落脚点时保留原开门/强开逻辑。近战敌人对木门／钢门连续3次实际单位受阻后，给出0.45秒提示和门闪，再强开并击退附近单位：玩家12伤害和短硬直，普通敌人28伤害，首领减弱。墙体／其他门阻挡及攻击者自身站错位不算单位卡门次数。
- 强开先校验完整门扇扫掠及击退路径，防止穿薄墙或落在开门叶片内；硬几何或无安全落脚点时不强行穿透。强开冷却3.5秒，新局清空计数／预警／冷却。
- 木门破坏后留下装饰碎片并移除门扇阻挡，门框保留；钢门可正常打开，关键路线不会要求破坏钢门。
- 敌人开局已在房间中，门缝通视后直接按实际视野显示。站在门外可以命中；关门后被遮住，原位置、生命和死亡状态继续保留。
- 开门、木门破坏、敌人受击会让对应房间警戒；未警戒的敌人原地待机，每 0.2 秒检查附近 360 距离内是否无遮挡地发现玩家。角色自己看见更远敌人时可以先记录房间发现，显示与受击始终即时生效。
- 近战敌人会砸木门，远程敌人和钢门交互采用开门。已警戒敌人可跨房间追击，首次警戒保留至少 0.35 秒攻击准备及原有攻击前摇；反复开关门不会重置其生命或冷却。
- 房间的“发现”和“进入过”分别记录。小地图区分已发现与已探索，用金色边框标出当前任务房间。
- 当前是受控转轴运动与几何碰撞，不模拟自由摆动、推门力矩或踢门。

## 样品内容

- 从二楼最西侧的凛的寝室出发，沿长廊向东进入值班室找楼梯钥匙，再折返中央楼梯间。下楼时淡出并加载一楼的专用贴图，生命、弹药、战术道具和强心剂次数延续。
- 一楼由门厅、两侧走廊、勤务通道、洗衣房、储物间和宿管室组成。打开或打坏宿管室门会触发警报，两批增援优先从视野外靠近。拾取大门钥匙并穿过门厅铁门即完成撤离。
- 学生、连帽衫、清洁工与保安四套丧尸外观共用近战属性。每局固定主要房间、门与撤离路线，从候选位置抽取两把钥匙、部分家具、初始敌人及增援。
- 枪口火光、烟雾、弹壳、弹道、命中粒子、音效、轻微镜头震动和翻滚无敌。
- 每清理一个已发现且有过敌人的区域恢复 20 生命，同一区域结算一次。两层的战斗数据合并结算。
- 3 名可用角色：凛（USP 消音手枪）、幽灵（AR-16 突击步枪）、维川（泵动式霰弹枪）；生命、移速、射速、弹匣与视距各不相同，配置见 `assets/scripts/Heroes.ts`。
- 新档赠送 3 张招募券；当前 `recruit` 固定产出幽灵，重复获得转为 30 材料。旧档中的退役角色已在存档迁移时退还票券与培养材料。
- “特勤档案 · 培养” → 角色“培养属性”：基础、移动速度、攻击速度分别升级，每项最高 10 级。
- 基础培养每级 +6 生命、+4% 基础伤害，消耗当前基础等级 ×30 材料；移速每级 +5% 基础移速，攻速每级 +8% 基础射速，两者各消耗对应当前等级 ×40 材料。
- 女主移速从 150 成长至 217.5；射速从约 2.08 发/秒成长至约 3.58 发/秒（最高攻速时单发间隔约 0.279 秒）。每项各自按基础值累计加成，角色之间独立保存；进入行动时采用培养后的属性。
- 视距由角色基础配置决定，档案中显示正面视距，培养详情同时显示近身视距；当前三项培养不改变视距。
- 失败奖励：10 + 击败数 ×3 材料、1 券；成功奖励：60 + 击败数 ×3 材料、2 券。奖励只结算一次。
- 档案、资源、等级与音效开关保存在本机（`sys.localStorage`，存储键沿用 `blackout.prototype.v1`）。存档内部版本为 v5，`readProfile` 逐版本迁移并清洗脏值：v1 主角更换、v2→v3 保留解锁与培养并重置移速／攻速等级、v4 退役角色退款。无账号、付费或联网功能；更换设备不共享存档。

美术为 ImageGen 纹理与代码绘制混合。凛与军人分别使用三帧翻滚图集与两套三帧倒地图集，军人动作帧由角色共用；持枪凛、幽灵、寝室家具和部分地面沿用已有素材。校园丧尸图集与提示词见 [0.12 美术素材](docs/art-prompts-v0.12.md)。部分角色站立模型及洗衣机、墙、门、标识、楼梯由代码绘制。

两层宿舍使用同一套公共地面装饰。素材、房间配置与生成提示词见 [公共地面装饰](docs/floor-details.md)。

女主与宿舍素材见 `docs/art-prompts-v0.5.md`；三帧翻滚素材路径、裁切参数与完整提示词见 `docs/art-prompts-v0.6.md`。素材均已保存至 `assets/resources/art/`，培养细节见 `docs/release-0.7.md`，视距与羽化见 `docs/release-0.8.md`，本轮敌人存在与房间警戒调整见 `docs/release-0.9.md`。

用户提供的战斗界面图集曾拆分为 12 个完整 UI 组件、透明预览页与坐标清单，产物保存在本机项目外的素材目录（未纳入本仓库）。游戏当前仍使用代码绘制的 HUD。

## 构建与检查

要求 Node.js ≥ 20.11（脚本使用 `import.meta.dirname`）。安装开发依赖后：

```powershell
npm ci                 # 干净环境；首次开发可用 npm install 生成 package-lock.json
npm run typecheck      # 26 个纯逻辑模块的严格类型检查，不需要 Cocos 编辑器
npm test               # 10 个脚本串联的全量回归
npm run check          # typecheck + test，CI 使用的组合
npm run build          # 构建横屏 H5，需要本机 Cocos Creator 3.8.8
npm run build:wechat   # 构建微信小游戏
npm run dev            # build + preview 一键试玩
```

`npm run build` 通过 `tools/build.ps1` 调用 Cocos Creator，默认路径为本机 3.8.8 安装目录；其他机器设置环境变量 `COCOS_CREATOR_PATH` 指向 `CocosCreator.exe`。`npm test` 与 `npm run typecheck` 使用 `devDependencies` 中的 TypeScript，**不需要**安装 Cocos 编辑器；CI（`.github/workflows/ci.yml`）即在干净的 Ubuntu 环境按此方式运行。

- `tsconfig.json`：Cocos 编辑器与 IDE 使用的项目配置，`extends ./temp/tsconfig.cocos.json`（`temp/` 由编辑器生成，含本机绝对路径，不入库）。
- `tsconfig.check.json`：不依赖 `temp/` 的独立检查配置，排除 3 个依赖 `cc` 声明的文件。
- `config/build-web-mobile.json`：横屏 H5 构建。
- `config/build-wechatgame.json`：微信小游戏构建配置。正式导入微信开发者工具时须填入自己的小游戏 AppID；未接入微信登录、广告、支付和云存档。
- `logs/`、`build/`、`temp/`：本机日志与产物，未纳入版本管理。
- `tools/test.mjs`：纯游戏逻辑回归，包括遮挡、碰撞、射击、换弹、养成、存档和结算。
- `tools/test-input.mjs`：读取真实场景挂载关系，以保留 Scene 禁止添加组件这一约束的引擎替身，检查启动、原生按钮、键鼠、移动端多指输入及暂停清理。它不替代浏览器、模拟器或真机测试。
- `tools/test-aim-assist.mjs`：辅助目标／主动脱离、存档兼容、严格射线与统一射击许可专项；手机多指和模式同步另由控制器测试覆盖。
- `tools/setup.mjs`：项目最初的场景、配置与音效生成器。日常开发无需重跑；它会重写已有场景和构建配置。

## 代码位置

完整模块地图见 [架构与模块索引](docs/ARCHITECTURE.md)。按层速查：

| 层 | 主要文件 |
| --- | --- |
| 纯玩法逻辑（不依赖 Cocos） | `Core.ts`（几何／视野／战斗／存档迁移）、`Levels.ts`（关卡布局与生成）、`Operation.ts`（第四章三阶段）、`Tactical.ts`（投掷物与声音传播）、`AimAssist.ts`（辅助瞄准意图）、`Heroes.ts`（角色配置） |
| 局外系统（纯逻辑） | `Shop.ts`、`WeaponMods.ts`、`LootCases.ts`、`Backpack.ts`、`DailyMissions.ts`、`CheckIn.ts`、`Achievements.ts`、`ClueReader.ts`、`Tutorial.ts`、`TutorialGuide.ts` |
| 表现与状态（纯逻辑） | `Presentation.ts`、`AmbientWildlife.ts`、`FloorDetails.ts`、`ExitGuide.ts` |
| 依赖 `cc` 的绘制与 UI | `Art.ts`（Graphics 绘制）、`TutorialGuideArt.ts`（教学示意）、`Blackout.ts`（场景启动、输入、全部界面、音效与存档写入） |
| 图集／裁切常量 | `TrainingArt.ts`、`ShopArt.ts`、`CaseArt.ts`、`BackpackArt.ts`、`CampaignArt.ts`、`OperationArt.ts` |
| 资源 | `assets/resources/effects/visibility.effect`（统一调色与视野合成）、`assets/resources/**`（美术与音效） |

玩法核心是纯 TypeScript，不依赖 DOM、HTML 控件或浏览器专属音频接口；29 个脚本中只有 3 个 `import ... from 'cc'`。这既让纯逻辑能在 Node 中直接回归，也为微信小游戏复用同一套玩法代码留出边界。H5 浏览器通过不等于微信真机通过；微信开发者工具及 iOS/Android 真机测试应独立记录。
