# 0.1.1 启动与输入修复

## 用户反馈

浏览器预览能看到设施，但没有主菜单、血条、弹药信息，键盘和鼠标均无响应。

## 根因

初始场景把 `Blackout` 直接挂载在 `cc.Scene` 上。脚本先创建了设施，随后执行 `this.node.addComponent(AudioSource)`。Cocos Creator 3.8.8 的 `Scene.addComponent()` 明确抛出 3822 错误，启动因此在注册输入和创建主菜单之前中断。

之前的纯战斗逻辑测试未执行 Cocos 场景初始化，因此没有覆盖这个问题。新增控制器检查最初以普通 Node 替代宿主，仍未保留 Scene 的约束；改为读取真实场景的宿主类型并让 Scene 替身保留禁止添加组件的行为后，修复前可以复现 3822 错误。

引擎依据：本机 `cocos/scene-graph/scene.ts` 的 `Scene.addComponent()` 实现；不是键盘配置或用户操作导致。

## 修复

- `Facility.scene`：业务组件移到普通子节点 `Game Bootstrap`，Scene 根组件列表为空。
- `Blackout.ts`：音频放在专用普通节点 `Combat audio` 上，即使旧的场景缓存暂未刷新，也不再向 Scene 添加音频组件。
- `setup.mjs`：同步修正初始场景生成器，避免重新生成时恢复错误挂载。
- 菜单和 HUD 点击操作改用 Cocos Button，交给引擎进行命中检测和单次点击派发。
- 桌面鼠标转换出的触摸事件不再触发手机摇杆；保留真实移动端多指操作。
- 鼠标和触摸坐标通过当前 UI 摄像机转换，匹配缩放及预览窗口尺寸。
- 主菜单新增 Enter 开始，暂停界面支持 Enter 继续。

## 验证范围

- 12 项纯游戏逻辑检查通过。
- 7 项控制器检查通过，包括真实场景挂载约束、完整启动、主菜单入口、键盘移动和释放、鼠标开火和停火、相机坐标转换、招募单次消耗、手机多指和暂停清理。
- TypeScript 检查通过。
- Cocos Web Mobile 构建通过；通过 HTTP 检查首页、控制器脚本和场景资源均返回 200，并确认构建产物包含新的普通启动节点及独立音频节点。
- 控制器检查使用非渲染的引擎替身，并非浏览器或真机输入验收。本次未完成浏览器自动实测，构建日志位于 `logs/build-web-mobile.log`。

## 重试方式

停止旧预览，重新打开 `assets/scenes/Facility.scene` 后启动浏览器预览。应先看到版本号为 0.1.1 的主菜单，再点击“进入设施”或按 Enter。进入战斗后应显示生命、区域与弹药，WASD 移动，鼠标左键射击。
