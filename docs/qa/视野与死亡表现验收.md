# 视野与死亡表现验收

已实现并通过自动回归、类型检查、Cocos web-mobile 构建与复用 8088 服务的 Chrome CDP 动态验收。移动固定朝向时半亮视距的周期摆动由基线 2.5px 降为 0px；独立死亡爆散、固定随机血迹、暂停与新局清理、终局表现延续均通过。

## 根因与修复

- Blackout.ts 旧代码每帧刷新严格演员 stencil，但软视野场以 30Hz/8px/0.03rad 缓存。shader 的 maskMotion 将整个旧视野纹理按玩家位移平移，因此连玩家中心视锥也跟着移动，重建时又归位。baseline 动态脚本在无障碍、固定朝向、每帧移动2.5px的90帧中记录到交替的215.75/213.25px半亮视距，跨度2.5px。
- 软场改为玩家位置/角度变化即同步重建，maskMotion置零。保持320×180分辨率、原有视距、96px范围羽化、12px遮挡羽化、严格演员mask以及独立B通道家具受光。静止时1秒刷新作为兜底，门几何revision立即刷新。
- 原距离场仅用二值格心作为边界种子，有4px逻辑格量化。改成边缘邻域真实线段距离种子，再做原有两遍传播；没有全图逐像素遍历所有线段。新增亚格平移连续性回归。视锥规则采样随朝向旋转，避免世界固定采样导致转向时圆弧分段改变。新增转向固定距离亮度回归。
- Shader资产已读取并核查，无需改shader公式；通过控制器传入零位移解决错误补偿。

## 死亡实现

Core.ts独立deathFragments，不依赖hp>0；每次阵亡仅触发一次，普通敌人10片、boss16片，全局128片上限，存活0.28–0.62秒。带旋转、阻力、抛起/落地状态和末段消退；尺寸边界walkable及线段检查防穿薄墙和飞出地板。Art.ts在严格演员mask下绘制碎块和血滴，尸体sprite移除不影响爆散。

血迹生成时一次性随机seed、大小、朝向、轮廓、外围血滴，并按当时遮挡生成固定轮廓/血滴坐标。绘制复用这些几何，不逐帧Math.random，不因随后开门或新增血迹改变旧轮廓。新Battle重置。原玩家死亡表现保留。

终局仍可在playing画面短暂推进碎块，但Battle.update终局分支只更新碎块，不推进敌人、玩家、计时、门、子弹或奖励。碎块结束后显示结果并结算一次。暂停不调用此推进。

## 实测性能与局限

纯CPU全视野基准（tools/test-presentation.mjs --bench，桌面Node环境）：530视距均值6.14ms/P95 7.96ms；265视距均值3.84ms/P95 6.92ms。详见visibility-cpu-bench.log。

浏览器90次确定性控制器更新（桌面Chrome headless/ANGLE SwiftShader）基线中位4.2ms/P95 9.7ms；最终final3中位4.3ms/P95 10.2ms、最大67.4ms。运行间存在JIT/GC/软件渲染噪声，不能据此宣称手机性能提升；未做手机真机CPU/GPU测量。移动/转向现在增加软场刷新频率，低端手机仍需真机回归；不以减视距、去遮挡或去羽化掩盖性能成本。
