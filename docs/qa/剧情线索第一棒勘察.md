## 几何核验

测试了 `createDormRun()` 的 64 个 seed（`0..63`），使用当前 `Battle.blockers`、`walkable()` 和 `visible()` 约束核对固定家具周边站位：

- `letter_alarm`（凛寝室书桌）可找到跨 64 seed 的固定可达候选，说明凛寝室可作为第一封信的落点。
- `letter_wall`（202 寝室书桌）在当前桌矩形和墙体几何下，64/64 个 seed 都没有找到同时满足 `walkable + lineClear` 的桌边候选。
- `warden_log`（一楼宿管室桌）在当前桌矩形和墙体几何下，64/64 个 seed 都没有找到同时满足 `walkable + lineClear` 的桌边候选。

原因：当前家具矩形既参与移动阻挡，也参与射线遮挡。若把交互逻辑点直接设在桌面矩形内部，严格视野一定被桌体挡住；若设在桌边外，202 寝室和宿管室的当前固定房间/家具布局又没有满足约束的安全站位。实现前必须先做一个明确的几何方案：

1. **推荐**：线索逻辑锚点设在桌面上方/桌边可见区域，视觉节点单独贴在桌面；同时为 202 桌和宿管桌保留专用站位（调整固定桌脚印或增加线索专用可见点），再用多 seed 回归。
2. 不推荐：放宽 `lineClear` 忽略家具。会使“严格可见/遮挡”失去现有语义，也可能让线索隔桌显示。
3. 不推荐：继续沿用随机 FloorDetails 的 paper/files；这违反固定线索、不能稳定交互，也无法区分地面装饰。

本棒没有修改正式源码、没有复制素材、没有运行 npm test/build；仅完成现场读取、真实素材核对和几何勘察。临时脚本由 `run_node` 执行，没有作为正式项目文件落地。
